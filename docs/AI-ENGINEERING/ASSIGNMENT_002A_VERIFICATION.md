# Assignment 002A implementation verification

Date: 10 October 2026. Status: ready for human review; not accepted or committed.

## Delivered behavior

PostgreSQL-backed anonymous attempts with shared Zod request/response contracts,
immutable prediction, explicit reference reveal, investigation, modification drafts,
bounded expression validation/retries, reflection/completion, and unassessed AI-use
declarations. Every implemented attempt operation checks bearer access and expiry.

Expressions remain plain text. Parser/interpreter enforce 200 characters, 50 nodes,
depth 12, allowed identifiers/operators, finite arithmetic, and division safety.
Five server-owned fixtures use absolute tolerance 1e-8. Only aggregate results and
published example feedback leave the API. Safe-but-failing checks permit reflection;
rejected expressions return 422 without advancement. Completed attempts reject writes.

Seven-day expiry is fixed at creation, enforced independently of deletion. Retain
at most 100 validation runs. Physical cleanup cascades evidence/history. Oversized
submissions preserve the previous bounded draft and are not persisted.

## Human source-review corrective verification — 10 October 2026

Scope: the requested blank-draft, reflect-stage recovery, and compiled-restart
corrections only. The preceding results remain the original checkpoint record.

Shared modification contracts already reject empty and whitespace-only text.
Validation requests deliberately accept plain strings so the bounded parser
returns actionable HTTP 422 rejection feedback. Added shared-schema regression
coverage and reused modificationSchema inside AttemptService before evidence
writes or advancement, closing the direct-service bypass. HTTP blank drafts
return 400 and stay at modify; blank validation returns 422 and stays at validate.

The existing latest-validation/current-draft guard blocks completion after a
rejected run at reflect. It now returns HTTP 409 REVALIDATION_REQUIRED with an
explicit instruction to safely revalidate the current draft. Service and HTTP
regressions cover safe evaluation, rejection with denominator feedback, blocked
completion without reflection evidence, restoring the earlier draft without
validation, and successful recovery after safe revalidation even when technical
checks fail. Rejected runs preserve reflect rather than advancing/completing.

The actual compiled-process restart test remains intact. Both server launches
now require HTTP 200 from /api/health, a valid shared health contract, and the
expected service identity. Startup diagnostics report readiness phase, exit
code/signal, and allowlisted error categories; raw stdout/stderr, request errors,
and response bodies are not emitted. An intentional pre-application Node startup
failure verifies lifecycle diagnostics and suppression of a synthetic private
marker. Startup/shutdown waits are bounded, and smoke cleanup remains restricted
to the attempt created by this test.
